# Research Analyst — endpoint matrix

Every surface a product of this class could take, with its state and the
repository evidence for that state. No silent gaps: a surface is LIVE,
BUILT, a reasoned N/A, WAIVER NEEDED (applicable but not built — a
Director decision), or WAIVED (the Director has granted the waiver). Audited 2026-11-04 against `main` plus the
`mcp-surface-2026-11-04` branch.

| Surface | State | Evidence |
|---|---|---|
| Website | LIVE | `ui/` static app served by `research_analyst/server.py` routes (`/`, `/help.html`, `/pricing.html`, `/privacy.html`, `/terms.html`, `/llms.txt`, `/manifest.json`, `/sw.js`). Canonical host analyst.thinkvalue.org; ra.aimlds.org redirects to it; ra.devinfo.dev mirrors. The F1.6 embed card (`GET /api/research/embed`) is part of this surface. |
| REST API | LIVE | `research_analyst/server.py`: `POST /api/research`, `POST /api/compare`, `POST /api/resolve`, `GET /api/research/quant`, `GET /api/usage`, scenarios + watchlists, `POST /api/billing/checkout` + webhook + claim. Wire contract: `research_analyst/api_models.py` (every payload is the `model_dump(mode="json")` of its model, `schema_version` on each). Auth + metering: `research_analyst/entitlements.py` (`KeyStore`, `MeteringRecorder`). Documented in `docs/API-REFERENCE.md`. Note: live charging arms only when the deployment's Stripe secret is configured — the checkout route answers 503 by design until then; that is a deployment-configuration fact, not a code gap. |
| MCP | BUILT (this branch; not yet deployed) | `POST /mcp` in `research_analyst/server.py`: streamable HTTP, JSON-RPC 2.0, stateless; methods `initialize`, `ping`, `tools/list`, `tools/call`; tools `research` and `quant` serving the same `_serve_research` / `_serve_quant` pipelines as REST. Auth rides the REST `KeyStore` (X-RA-Key or Authorization: Bearer), keyed-lane rate cap + monthly allowance, metering under the `mcp` label. Auth posture — a valid API key is required on /mcp whenever a key store is configured — RATIFIED by the Director, 2026-11-04. Tests: `tests/test_mcp.py`. Draft registry entry: `server.json` (unsubmitted). First consumer waiting: Sail's `sail/raclient.py` (`SAIL_RA_MCP_URL` / `SAIL_RA_MCP_TOOL` / `SAIL_RA_MCP_TOKEN`). Goes LIVE only when this branch is deployed. |
| Email | LIVE (contact channel only) | Support contact is `info@aimlds.org`, published in `ui/help.html`, `ui/privacy.html`, and the seller strip on every page. There is deliberately no outbound-mail product surface: no mail-sending code exists anywhere in `research_analyst/` (no SMTP/send path) — reports are delivered over the web/API/MCP surfaces, not by email. |
| CLI | BUILT | Console script `research-analyst` (`pyproject.toml` `[project.scripts]` → `research_analyst/cli.py:main`). Terminal UI: `research_analyst/tui_app.py` + `research_analyst/tui.py` (the `tui` optional dependency, textual). |
| Browser extension | N/A | No extension code exists, and none is planned: everything an extension could add (act on a ticker seen on another page) is already covered by the web app and the F1.6 embed card, which is the sanctioned in-page surface. A research product whose outputs must carry provenance and disclaimers gains nothing from a browser-resident surface. Revisit only on demonstrated demand. |
| Desktop (native GUI) | WAIVED | Terminal use is covered by the TUI (see CLI). A native desktop app does not exist. The long-term direction on record — a local app with the engine sealed on-device and fresh data syncing in — is a separate end-state program, not a wrapper job; whether and when to build it is a Director decision. Waiver granted by the Director, 2026-11-04: "I accept that RA will not have a desktop GUI or an iOS app." |
| Android | BUILT | Capacitor WebView wrapper over the same `ui/` codebase: `capacitor.config.js` (appId `com.research.analyst`, loads https://ra.devinfo.dev), `package.json` (`cap:*` scripts, Capacitor 6 dependencies). Build + distribution are documented in `docs/ANDROID_BUILD.md`: CI workflow staged at `deploy/github-actions/android-apk.yml` (activation is one manual paste into `.github/workflows/`, per that doc), distribution is F-Droid + direct APK — Play Store is skipped by design. The `android/` native project is generated by `cap add android`, not committed. |
| iOS | WAIVED | The Capacitor path exists on paper only: `@capacitor/ios` is a declared dependency and `cap:add:ios` scripts are present in `package.json`, but there is no iOS build doc, no generated `ios/` project, and no distribution route (no App Store or sideload equivalent of the Android plan). Building it out is a Director decision. Waiver granted by the Director, 2026-11-04: "I accept that RA will not have a desktop GUI or an iOS app." |

## Reading rules

- LIVE means deployed and serving. BUILT means code-complete in the
  repository with tests, awaiting deploy or packaging steps the cited
  doc names.
- States are claimed from repository evidence only. Anything a live
  probe would be needed to confirm (for example, whether a staged CI
  workflow has since been activated) is stated as such in the row,
  not assumed.
